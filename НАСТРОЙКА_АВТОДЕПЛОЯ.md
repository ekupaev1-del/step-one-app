# 🚀 Настройка автоматического деплоя в Vercel

## Способ 1: Через Vercel Dashboard (РЕКОМЕНДУЕТСЯ - самый простой)

### Шаг 1: Подключите GitHub репозиторий

1. Откройте [Vercel Dashboard](https://vercel.com/dashboard)
2. Нажмите **"Add New Project"** или **"Import Project"**
3. Выберите ваш GitHub репозиторий `step-one-app`
4. Нажмите **"Import"**

### Шаг 2: Настройте проект

**ВАЖНО:** Укажите эти настройки:

- **Root Directory**: `miniapp` ⚠️ (ОБЯЗАТЕЛЬНО!)
- **Framework Preset**: Next.js (определится автоматически)
- **Production Branch**: `main`
- **Build Command**: `npm run build` (уже настроено в vercel.json)
- **Output Directory**: `.next` (уже настроено в vercel.json)
- **Install Command**: `npm install` (уже настроено в vercel.json)

### Шаг 3: Добавьте переменные окружения

В разделе **Environment Variables** добавьте для **Production**, **Preview** и **Development**:

```
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<service-role-key>
EXPECTED_SUPABASE_PROJECT_REF=<project-ref>
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-key>
```

### Шаг 4: Нажмите "Deploy"

Готово! 🎉

## Способ 2: Через Vercel CLI

### Шаг 1: Установите Vercel CLI

```bash
npm install -g vercel
```

### Шаг 2: Авторизуйтесь

```bash
vercel login
```

### Шаг 3: Подключите проект

```bash
cd miniapp
vercel link
```

Следуйте инструкциям:
- Выберите или создайте проект
- Укажите Root Directory: `miniapp` (или оставьте по умолчанию, если уже в miniapp)

### Шаг 4: Деплой

```bash
# Preview деплой
vercel

# Production деплой
vercel --prod
```

## Способ 3: Через GitHub Actions (автоматический деплой при push)

### Шаг 1: Добавьте Secrets в GitHub

Зайдите в ваш GitHub репозиторий:
**Settings → Secrets and variables → Actions → New repository secret**

Добавьте следующие secrets:

- `VERCEL_TOKEN` - получите на https://vercel.com/account/tokens
- `VERCEL_ORG_ID` - найдите в Vercel Dashboard → Settings → General
- `VERCEL_PROJECT_ID` - найдите в Vercel Dashboard → Settings → General
- `NEXT_PUBLIC_SUPABASE_URL` - ваш Supabase URL
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` - ваш Supabase anon key
- `SUPABASE_SERVICE_ROLE_KEY` - ваш Supabase service role key
- `SUPABASE_URL` - ваш Supabase URL

### Шаг 2: Push в GitHub

Workflow автоматически запустится при push в `main` или `dev`:

```bash
git push origin main
```

## ✅ После настройки

**Автоматический деплой работает!**

Теперь каждый push в GitHub автоматически запускает деплой:

```bash

```

**Vercel автоматически:**
- ✅ Определит изменения в Git
- ✅ Запустит сборку проекта
- ✅ Задеплоит новую версию
- ✅ Обновит URL

## 🔧 Использование скриптов для деплоя

### Windows (PowerShell):

```powershell
.\deploy.ps1              # Preview деплой
.\deploy.ps1 production    # Production деплой
```

### Linux/Mac (Bash):

```bash
chmod +x deploy.sh
./deploy.sh              # Preview деплой
./deploy.sh production    # Production деплой
```

## 📊 Мониторинг деплоев

- **Vercel Dashboard** → **Deployments** → список всех деплоев
- Каждый push создаёт новый deployment автоматически
- Preview деплои доступны по уникальным URL
- Production деплои обновляют основной домен

## 🐛 Решение проблем

### Деплой не запускается:
- ✅ Проверьте, что Root Directory = `miniapp` в настройках проекта Vercel
- ✅ Проверьте, что репозиторий подключен в Vercel
- ✅ Проверьте, что есть push в Git (Vercel реагирует на push)

### Ошибка сборки:
- ✅ Проверьте логи в **Vercel Dashboard → Deployments → [выберите деплой] → Build Logs**
- ✅ Проверьте, что все переменные окружения установлены
- ✅ Проверьте, что `package.json` содержит правильные скрипты

### Переменные окружения не работают:
- ✅ Убедитесь, что переменные добавлены для всех окружений (Production, Preview, Development)
- ✅ Перезапустите деплой после добавления переменных
