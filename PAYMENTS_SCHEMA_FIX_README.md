# Payments Schema Fix - Complete Guide

## Problem

PostgREST/Supabase schema cache errors when calling `POST /api/payments/start`:
- "Could not find the 'method' column of 'payments' in the schema cache"
- Previously: 'currency', 'plan_code', NOT NULL violations on telegram_user_id/inv_id

## Solution

Complete rebuild of payments persistence layer with:
1. Correct database schema matching API insert payload exactly
2. PostgREST schema cache reload after migrations
3. Enhanced error handling and debug output
4. Proper validation and field generation

## Migration Steps

### 1. Apply Database Migration

**Execute in Supabase SQL Editor:**

1. Open Supabase Dashboard → Your Project → SQL Editor
2. Open file: `migrations/20241220_fix_payments_schema_complete.sql`
3. Copy entire SQL content
4. Paste into SQL Editor
5. Click "Run" or press Ctrl+Enter
6. Wait for success message

### 2. Reload PostgREST Schema Cache

**CRITICAL:** After applying the migration, you MUST reload the schema cache.

**Option A: Via SQL Editor (Recommended)**
```sql
SELECT pg_notify('pgrst', 'reload schema');
```

**Option B: Via API Endpoint**
```bash
curl -X POST https://your-app.vercel.app/api/admin/reload-schema \
  -H "Authorization: Bearer YOUR_ADMIN_SECRET"
```

**Option C: Wait 1-2 minutes**
PostgREST will auto-reload, but this is slower.

### 3. Verify Schema

Run this in SQL Editor to verify all columns exist:

```sql
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns 
WHERE table_name = 'payments' 
ORDER BY ordinal_position;
```

**Expected columns (in order):**
- id (uuid, PK)
- user_id (integer, NOT NULL)
- telegram_user_id (text, NOT NULL)
- inv_id (text, NOT NULL, UNIQUE)
- method (text, NOT NULL, default 'card')
- plan_code (text, NOT NULL)
- amount (numeric, NOT NULL)
- currency (text, NOT NULL, default 'RUB')
- status (text, NOT NULL, default 'created')
- payment_url (text, nullable)
- provider (text, NOT NULL, default 'robokassa')
- created_at (timestamptz, NOT NULL, default now())
- updated_at (timestamptz, NOT NULL, default now())

## API Insert Payload

The API route `/api/payments/start` inserts exactly these fields:

```typescript
{
  user_id: number,           // from request: userId
  telegram_user_id: string,  // from request/initData: telegramUserId

  method: "sbp" | "card",    // from request: method
  plan_code: string,         // from request: planCode
  amount: string,            // calculated: amount (e.g., "199.00")
  currency: "RUB",           // hardcoded: "RUB"
  status: "created",         // hardcoded: "created"
  payment_url: string,       // from provider: paymentUrl
  provider: "robokassa",     // hardcoded: "robokassa"
  // created_at and updated_at are auto-generated by DB
}
```

## Troubleshooting

### "Could not find the 'method' column"

**Cause:** Schema cache not reloaded after migration.

**Fix:**
1. Run: `SELECT pg_notify('pgrst', 'reload schema');` in SQL Editor
2. Wait 10-30 seconds
3. Try again

### "NOT NULL violation on telegram_user_id"

**Cause:** Migration didn't fix existing NULL values.

**Fix:**
1. Check for NULL values: `SELECT * FROM payments WHERE telegram_user_id IS NULL;`
2. Update them: `UPDATE payments SET telegram_user_id = 'unknown_' || id::text WHERE telegram_user_id IS NULL;`
3. Ensure column is NOT NULL: `ALTER TABLE payments ALTER COLUMN telegram_user_id SET NOT NULL;`

### "NOT NULL violation on inv_id"

**Cause:** inv_id not generated before insert (should not happen with new code).

**Fix:**
1. Check API logs - inv_id should be generated before insert
2. Verify `generateInvoiceId()` is called before insert
3. Check for NULL values and fix: `UPDATE payments SET inv_id = 'unknown_' || id::text WHERE inv_id IS NULL;`
