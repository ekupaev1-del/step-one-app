# Инструкция по тестированию системы подписки

## Предварительная настройка

1. **Применить миграции БД в Supabase:**
   - Выполните `migrations/create_payments_table_v2.sql`
   - Выполните `migrations/create_subscriptions_table_v2.sql`

2. **Настроить Environment Variables в Vercel:**
   ```
   ROBO_MERCHANT_LOGIN=your_merchant_login
   ROBO_PASSWORD1=your_password1
   ROBO_PASSWORD2=your_password2
   ROBO_IS_TEST=true  # или false для продакшена
   APP_BASE_URL=https://your-domain.vercel.app
   CRON_SECRET=your_secret_for_cron
   ```

3. **Настроить Robokassa:**
   - Result URL: `https://your-domain.vercel.app/api/payments/webhook`
   - Success URL: `https://your-domain.vercel.app/api/payments/return`

## Проверка рекуррентных платежей

1. **Настроить cron в Vercel:**
   - Добавить CRON_SECRET в environment variables
   - Cron job настроен в `vercel.json` (каждые 6 часов)

2. **Тестирование:**
   - Создать подписку с `next_charge_at` в прошлом
   - Запустить cron endpoint вручную:
     ```bash
     curl -H "Authorization: Bearer YOUR_CRON_SECRET" \
          https://your-domain.vercel.app/api/cron/recurring-charges
     ```
   - Проверить создание нового платежа в БД
   - Проверить обновление `next_charge_at`

## Возможные проблемы

1. **"Платежный провайдер не настроен"**
   - Проверить наличие всех ROBO_* переменных в Vercel
   - Проверить, что переменные не пустые

2. **Ошибка открытия ссылки на оплату**
   - Проверить доступность Telegram.WebApp
   - Проверить fallback на window.location.href

3. **Подписка не активируется после оплаты**
   - Проверить логи webhook endpoint
   - Проверить верификацию подписи
   - Проверить обновление записи в БД

4. **Ошибки миграции**
   - Убедиться, что таблицы не существуют или использовать безопасную миграцию
   - Проверить права доступа к БД
